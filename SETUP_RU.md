## 2. Создай Telegram-бота

> ⚠️ **Твой токен утёк в чат — его нужно перевыпустить.** Это первое, что
> сделай. Старый токен больше нигде не используй.

1. Открой Telegram и найди **@BotFather**.
2. Если бот уже есть — отправь `/mybots` → выбери бота → **API Token** → **Revoke**.
   BotFather выдаст **новый** токен.
3. Если бота ещё нет — отправь `/newbot`, придумай имя и username
   (заканчивается на `bot`, например `my_ai_2026_bot`).
4. BotFather пришлёт токен вида `123456789:ABCdef...`.
5. Скопируй его — он пригодится в шаге 6.

> ⚠️ **Токен — это пароль от бота.** Кто его знает, тот может читать все
> сообщения бота и писать от его имени. Не вставляй токен в чаты, скриншоты и
> GitHub. Если токен куда-то утёк — отправь BotFather команду `/revoke` и получи новый.

## 9. Деплой на Render

1. Войди на [render.com](https://render.com) → **Sign in with GitHub**.
2. Нажми **New → Blueprint**.
3. Выбери свой репозиторий → **Connect**.
4. Render прочитает `render.yaml` и попросит заполнить **два** поля:

   | Ключ | Значение |
   | --- | --- |
   | `BOT_TOKEN` | новый токен от BotFather (шаг 2) |
   | `GEMINI_API_KEY` | ключ из Google AI Studio (шаг 3) |

   Остальное Render настроит сам:
   - `WEBHOOK_SECRET` — сгенерирует случайный;
   - `GEMINI_MODEL` / `GEMINI_FALLBACK_MODEL` — уже прописаны;
   - адрес сервиса для webhook — подставится автоматически (переменная
     `RENDER_EXTERNAL_URL`), вручную ничего указывать не нужно.

5. Нажми **Apply**. Начнётся деплой (3–5 минут). Дождись статуса **Live**.

> ✅ Раньше нужно было вручную вписывать `PUBLIC_URL` и передеплоить — теперь
> это не требуется, всё делается в один заход.

## 11. Держи бота онлайн 24/7

Render Free **засыпает** после ~15 минут без входящих запросов. Первый ответ после сна будет с задержкой 30–60 секунд. Чтобы бот «просыпался» автоматически:

### Способ: cron-job.org (полностью бесплатно)

1. Зайди на [cron-job.org](https://cron-job.org) → **Register**.
2. Нажми **Add cronjob**.
3. Настройки:
   - **Active**: ✅
   - **URL**: `https://твой-сервис.onrender.com/health`
   - **Interval**: каждые 5 минут
   - **Method**: GET
   - **User-Agent**: `Mozilla/5.0`
4. Нажми **Add cronjob**.

Готово! Каждые 5 минут сервис будет получать лёгкий запрос и «просыпаться».

## 15. Частые ошибки

| Ошибка | Решение |
| --- | --- |
| `KeyError: 'BOT_TOKEN'` | Проверь, что BOT_TOKEN и GEMINI_API_KEY заданы в Render |
| `Нет соединения с Telegram (ConnectTimeout)` | Telegram блокирует провайдер — см. раздел ниже |
| `404 NOT_FOUND` от Gemini | Проверь название модели — см. [ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models) |
| `429 RESOURCE_EXHAUSTED` | Исчерпан бесплатный лимит. Подожди минуту — бот сам попробует резервную модель |
| `getMe: Unauthorized` | Неверный BOT_TOKEN |
| `blocked` от Telegram | Перезапусти сервис на Render |
| Бот молчит на Render | Открой `https://твой-url/health` в браузере, затем проверь **Logs** в Render |
| Ошибка `Invalid markdown` | Бот автоматически переведёт ответ в plain text |

## 15.1. Если Telegram заблокирован провайдером

У некоторых провайдеров (частая ситуация в РФ) `api.telegram.org` недоступен:
соединение просто зависает. Проверить это можно так:

```
python check_setup.py
```

Если увидишь «Интернет есть (Google отвечает), но Telegram заблокирован» —
код и токен тут ни при чём, блокировка на уровне сети.

**Что это значит:**

- **Локальный запуск (`python bot.py`) без VPN не заработает.** Бот не сможет
  достучаться до Telegram — это ожидаемо, не баг.
- **На Render всё будет работать.** Серверы Render находятся вне этой сети,
  им Telegram доступен и на отправку, и на приём. Деплой — шаги 8–11.

**Варианты:**

1. **Рекомендуется:** пропусти локальный тест, сразу разверни на Render (шаг 8).
2. Включи **VPN** — тогда локальный запуск заработает. Если у VPN есть
   локальный прокси, укажи его в `.env`: `HTTPS_PROXY=http://127.0.0.1:порт`
   (бот подхватит его автоматически).

## 17. Куда девается память диалога

История хранится в файле `memory.db` на бесплатном Render. Когда Render
пересоздаёт экземпляр сервиса (например, после редиплоя), история обнуляется.
Это нормально: бот продолжает работать, просто перестаёт помнить прошлые реплики.
Если нужна постоянная память — позже подключают бесплатную PostgreSQL (Neon/Supabase).
